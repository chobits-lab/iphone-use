# Recording a demo (optional)

Read this only when the user wants the run recorded or shown publicly.

## Before recording

- Connect the mirror, finish any sign-in the owner needs, and test the input route with a short piece of text before the real take.
- Record only what the host allows, usually just the iPhone Mirroring window. If the host refuses to capture a window, don't work around it with another recorder.
- Never record sign-ins, passwords or codes. If authentication comes up mid-take, stop, and start a new take after recovering.

## While recording

- Log each action's time relative to the start of this take, so edits line up with the picture. If the window size changes, recompute coordinates.
- Hold the result screen for at least three seconds with the pointer moved away from the text.

## Editing

- Waits and retries can be cut or sped up, but label the speed-up; don't present it as one clean run with no help.
- Captions, status markers and log excerpts are added in editing; don't make them look like native phone UI or live footage.
- An unsent reply can't be called "replied"; say so when the owner helped.

## Masking

- Mask contact names and avatars, account names, personal addresses and maps. Place names, ratings, prices, dates, times and buttons can stay; don't black out half the screen.
- Animations leak most: sheets sliding, the app switcher, keyboard suggestions, text wrapping, map previews. A mask that covers the still frame can miss the motion, so treat transitions separately.
- After export, step through the opening, the transitions and the result frames. OCR helps but isn't enough; check avatars and maps by eye.
- Keep raw recordings apart from masked cuts. A skill package holds only general methods and made-up examples, never recordings, login state or personal task notes.
